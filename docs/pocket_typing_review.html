Pocket Typing: Physics vs Over-Engineering

Review of pocket_typing.py + pocket_framework_env.py — method shape_refined

2026-05-27 · Mofography / mgr_cli_py

TL;DR: The core design intent — PSD peak diameter (d₁) as primary signal, annulus fingerprint as tiebreaker — is sound physics. The implementation has drifted into a cascade of magic numbers and case-specific gates tuned to pass benchmarks. Three critical problems:
  1. Fingerprint annulus is centered at void centroid, not pocket maximum — physically inconsistent for non-spherical pockets.
  2. split_band_by_max_r_subpeaks only splits for ZIF-like pockets (max_r < 4 Å) — fingerprints are silently ignored for larger pockets.
  3. d₁ values are unreliable for ZIF-like windows — the "d₁-first" primary logic is undermined.

Pipeline Architecture

User's intent: PSD peaks are sharp delta functions → primary classification signal. When peaks are poorly separated (grid discretization, multiple same-size pockets) → use a rotation-invariant annulus fingerprint around the pocket maximum as the tiebreaker.

Current 4-stage pipeline (assign_pocket_types_shape_refined):

  1. 1
    d₁ coarse grouping (group_pockets_by_d1_coarse)
    Sort pockets by PSD peak diameter d₁; greedy merge if gap ≤ 0.5 Å. Good in principle, but depends on reliable d₁ values (see Issue 3).
  2. 2
    Conditional max_r refinement (_within_d1_group_use_max_r_refinement)
    Sub-band by max probe radius — but only if the band has >12 pockets AND specific conditions. This gate is a benchmark-tuning hack (see Issue 4).
  3. 3
    Fingerprint subsplit (split_band_by_max_r_subpeaks)
    Within one max_r band: split if fingerprints disagree — but in practice only fires for max_r < 4 Å (see Issue 2).
  4. 4
    Adjacent-group merge (merge_adjacent_groups_by_fingerprint)
    Union-merge neighboring groups when fingerprints agree. Reasonable design; complicated by multiple cosine threshold variants (Issue 5).

What Is Working Well

  • GOOD PSD as primary signal — physically correct; PSD peaks are distinguishable in most MOFs.
  • GOOD SH power spectrum for rotation invariance — |alm|² summed over m is mathematically rotation-invariant.
  • GOOD Element-resolved channels (per_z_radial, per_z_sh_power) — chemistry-aware; Zn vs Cu framework atoms are treated differently even with same geometry.
  • GOOD MIC wrapping of void points to dgrid peak — correct for PBC systems; fragments spanning the cell boundary are properly handled.
  • GOOD PBC painting bug fixed — all periodic copies of the same pocket now get the same type label.
  • GOOD max_probe_radius via PBC fragment group — takes max over all fragment labels; correct for split periodic pockets.
  • GOOD Annulus concept — selecting atoms near the cavity mouth (not the whole framework) is the right physical choice.

Critical Issues

BUG HIGH Issue 1: Annulus centered at void centroid, not pocket maximum ▶

In compute_pocket_fingerprint, the void points are MIC-wrapped to the dgrid peak, but then the mean (centroid) of all void points is used as the descriptor origin:

void_pts = void_cart_mic_for_fragment_group(...)  # all void voxels, wrapped to peak
centroid = pocket_centroid(void_pts)              # mean of ALL void points  ← problem
...
dr = mic_vectors_from_centroid(atoms, centroid, a_idx)  # from centroid, not peak
r  = np.linalg.norm(dr, axis=1)
# Annulus filter:
r_lo = max(0.5, max_probe_radius_a - 0.3)   # defined relative to max_probe
r_hi = max_probe_radius_a + 2.0
mask = (r >= r_lo) & (r <= r_hi)            # applied to centroid-distances

The physics mismatch: The annulus bounds [max_probe − 0.3, max_probe + 2.0] Å are physically meaningful relative to the pocket maximum — the single point where the probe sphere is largest. The "mouth atoms" are those closest to this maximum. But the distances r are measured from the void centroid, which for non-spherical pockets (corner fragments, wall half-pockets) can be displaced 2–4 Å from the maximum.

Consequence: For a corner fragment with centroid inside a wall, the annulus [2.7, 5.0] Å from the centroid captures atoms that have nothing to do with the pocket mouth. For a large mesopore, centroid ≈ maximum so it accidentally works.

Fix: Use void_near_peak=True in the production call to compute_pocket_fingerprints, or directly compute dr from peak_cart (argmax of dgrid) rather than centroid. The function void_cart_near_dgrid_peak already exists for this purpose.

The parameter exists but is never used in the production path:

# In compute_pocket_fingerprints (pocket_typing.py):
fps[rep] = compute_pocket_fingerprint(
    regions_pbc, regions, dgrid, rep, shape, atoms, bonds,
    r_pocket=float(p["d1_A"]),
    max_probe_radius_a=mr,
    void_volume_a3=vol,
    fragment_group=frag_group,
    # void_near_peak=True  ← THIS IS NEVER SET
)
BUG HIGH Issue 2: split_band_by_max_r_subpeaks only splits ZIF-like pockets — fingerprints are silently ignored for max_r ≥ 4 Å ▶

The function that is supposed to use fingerprints to decide splits has only one actual split branch:

def split_band_by_max_r_subpeaks(...):
    if spread <= 0.045:
        return [list(pocket_ids)]           # 1. early exit: spread too small

    cos_full = fingerprint_cosine_similarity(fa, fb, angular_only=False)
    if cos_full >= split_cosine:            # 2. fingerprints agree → keep merged
        return [list(pocket_ids)]

    if max(d1a, d1b) <= 8.0:              # 3. small pocket: angular-only escape
        cos_ang = fingerprint_cosine_similarity(fa, fb, angular_only=True)
        if cos_ang >= 0.94:
            return [list(pocket_ids)]

    # THE ONLY ACTUAL SPLIT BRANCH:
    if max(max_rs) < 4.0 and spread >= 0.04 and cos_full < split_cosine:
        return [sorted(v) for v in ...]

    return [list(pocket_ids)]              # ← FALLBACK: always no-split

The bug: For any pocket with max_r ≥ 4 Å — even if fingerprints are completely different (cos = 0.0, spread = 1.0 Å) — the function falls through to the final return [list(pocket_ids)] and returns the unsplit list. The fingerprint disagreement is computed but then completely discarded.

This is directly contradicted by the design intent. The function docstring says: "Split one max_r band when grid peaks differ in radius and annulus fingerprint disagrees." But the implementation only acts on this for ZIF-like windows.

Fix: The split condition should be symmetric — if fingerprints disagree (cos < threshold) AND spread exceeds the gap, split. Remove the max_r < 4.0 gate:

if spread >= subsplit_gap_a and cos_full < split_cosine: → split by peak

The n ≤ 12 → skip max_r entirely gate in _within_d1_group_use_max_r_refinement is the other half of this problem — it prevents this function from even being called for NU-1000/IRMOF. Once the fingerprint logic is correct, that gate can be removed.

PHYSICS HIGH Issue 3: d₁ values are unreliable for quantized/small windows — "d₁-first" primary logic is undermined ▶

The handoff documents a known problem:

For some reps, pockets[].d1_A (e.g. 2.88 Å on ZIF) does NOT match the argmax of the stored pocketwise PSD curve (often ~5.1–5.6 Å diameter).

In practice for ZIF-20, most window pockets get d1_A ≈ 2.88 Å even though their true PSD peaks span 5.1–5.6 Å. This puts all ~100 ZIF window pockets into a single d₁ coarse band, after which max_r becomes the de-facto primary discriminator — not d₁. The stated design principle is d₁-first, but ZIF behavior is max_r-first in disguise.

Root cause candidates:

  • PSD bin edges (0.25 Å bins) cause many pockets to share the same bin value.
  • The PBC-group PSD may average or take the max over fragments; individual fragment peaks wash out.
  • The d1_A = argmax(psd_y_pbc) extraction may be using pre-normalization values or falling back to bin index 0 when normalization fails.
Validation needed: Print psd_x[argmax(psd_y_pbc)] vs pocket["d1_A"] for ZIF-20 reps and confirm they match. If they don't, the d₁-first architecture is built on a broken signal.
OVER-ENGINEERED MEDIUM Issue 4: Magic "n ≤ 12 → skip refinement" gate — hardcoded benchmark fix, not physics ▶ 
def _within_d1_group_use_max_r_refinement(grp, fps):
    n = len(grp)
    max_r_vals = [fps[int(p)].max_probe_radius_a for p in grp]
    spread = max(max_r_vals) - min(max_r_vals)

    if n <= 12:              # ← NO PHYSICS JUSTIFICATION
        return False         # skip max_r refinement entirely

    if n >= 8 and max(max_r_vals) < 5.0:   # ZIF-like
        return True
    if n >= 8 and spread >= 0.10:
        return True
    return False

The n ≤ 12 rule exists purely to prevent NU-1000 and IRMOF-1 from being over-split. NU-1000 has 12 pockets in one d₁ band; without this gate, max_r refinement splits wall/corner/edge fragments into separate types. The "fix" was to skip max_r for all bands with ≤12 pockets.

Why this is wrong: UiO-66 also has 12 pockets in its micropore band (max_r ~3.5 Å), and also benefits from this gate. But the gate fires for any band ≤12, including cases where max_r genuinely differs. The count threshold has no physical meaning — it's an accident that it works for the benchmarked MOFs.

The ZIF-like condition (max_r < 5.0) is also not a physical threshold. It was tuned so ZIF-20 gets refinement. But UiO-66 has max_r ≈ 3.5 Å (less than 5.0), so the interaction between these two conditions creates an accidental fix: UiO-66 has n=12 ≤ 12, so the ZIF-like check is never reached.

Correct approach: Let the fingerprint do the work. If wall/corner/edge fragments of NU-1000 are the same pocket type, their fingerprints will agree (high cosine) and no split will occur naturally — without any count-based gate.

PHYSICS MEDIUM Issue 6: Split decision compares only the extreme (lowest + highest) max_r peaks, ignoring middle peaks ▶ 
peaks = sorted(by_peak.keys())
rep_a = min(by_peak[peaks[0]], ...)    # lowest max_r bin
rep_b = min(by_peak[peaks[-1]], ...)   # highest max_r bin
cos_full = fingerprint_cosine_similarity(fa, fb)  # only compare extremes

If a band has 3 or more discrete max_r bins (e.g. 2.74, 2.79, 2.84 Å), the middle peak is completely ignored in the comparison. The decision to split or not is made solely from the fingerprint cosine between the extremes.

This can cause incorrect merges: if the 2.74 and 2.84 groups have similar fingerprints by coincidence, but the 2.79 group is genuinely different, the function will return the entire band unsplit.

Fix: For N grid peaks, use single-linkage clustering: compute cosine for all N−1 adjacent pairs; split at any pair where cosine < threshold.
PHYSICS LOW Issue 7: Adaptive shell radius uses void centroid but annulus bounds use max_r from peak — mixed reference frames ▶

Two radius computations in the same function use different reference points:

  1. Adaptive shell pre-selection: r_shell = clip(1.1 × r_scale + 2.0, 2.0, ∞) — atoms within this radius of the void centroid are collected first.
  2. Annulus filter: [max_probe − 0.3, max_probe + 2.0] Å from the centroid, but the bounds are defined by max_probe_radius_a which is the dgrid value at the peak.

For a large mesopore (max_r ≈ 10 Å, centroid ≈ peak): r_shell ≈ 24 Å, annulus [9.7, 12.0] Å — consistent.

For a small ZIF window (max_r ≈ 2.7 Å, centroid may be 2 Å off peak): r_shell ≈ 8.6 Å, annulus [2.4, 4.7] Å from centroid. If centroid is off-peak by 2 Å, the annulus misses the actual mouth atoms entirely.

This is a consequence of Issue 1 and resolves when the centroid is fixed to the peak position.

Proposed Simpler Design

Principle: The fingerprint should be the sole arbiter for disambiguation. The PSD d₁ provides coarse grouping; the annulus fingerprint — correctly centered — provides fine splitting/merging. No count-based gates, no per-case cosine variants.

Stage 1 — PSD d₁ coarse groups (keep, but fix d₁ extraction)

Sort by d₁; merge adjacent if gap ≤ τ (0.5 Å). First validate that d1_A = psd_x[argmax(psd_y_pbc)] for every pocket. Without reliable d₁, this step is unreliable for ZIF.

Stage 2 — Within coarse group: fingerprint clustering (replace max_r+gates)

For each coarse d₁ group, use fingerprint cosine to cluster pockets. Simple single-linkage at threshold 0.85 (or average-linkage). No max_r band step, no count-dependent gates. The fingerprint naturally encodes the pocket environment:

  • Wall/corner/edge of the same cage type → similar SH spectrum → high cosine → one cluster
  • Different opening size/environment → different SH spectrum → low cosine → separate clusters

Stage 3 — Adjacent-group merge (simplify)

If two adjacent coarse groups have mean fingerprint cosine ≥ threshold AND d₁ gap ≤ τ + gray → merge. No probe-gap gate needed if fingerprint is correctly computed.

Required fingerprint fix

Center the annulus at the dgrid maximum position, not the void centroid:

# Option A: use void_near_peak=True (existing code path, currently unused)
fps[rep] = compute_pocket_fingerprint(
    ...,
    void_near_peak=True,   # ← add this
    fragment_group=frag_group,
)

# Option B: compute peak_cart and pass as centroid override (more explicit)
# peak_cart = find_coord_from_indices(argmax_idx, shape, atoms)
# dr = mic_vectors(atoms, peak_cart, a_idx)   ← use peak, not centroid

Annulus bounds from the peak position: [max_r − 0.5, max_r + 2.5] Å captures exactly the atoms forming the cavity mouth.

Alternatively, thread peak_cart through to use as the MIC reference point for mic_vectors_from_centroid. Remove the if max(max_rs) < 4.0 gate. The split condition should simply be: spread ≥ subsplit_gap AND fingerprint cosine < threshold → split. This makes the fingerprint the actual arbiter rather than a dead check for non-ZIF pockets.

Once Issues 1+2 are fixed, replace _within_d1_group_use_max_r_refinement with a simple fingerprint clustering step applied uniformly to all coarse d₁ groups. Wall/corner fragments of the same cage will naturally cluster together (high cosine), eliminating the need for a count-based gate.

P2
Remove dead code: FP_SPLIT_COSINE, FP_SMALL_POCKET_COSINE

FP_SMALL_POCKET_COSINE = 0.96 is imported in pocket_typing.py but never used in the split function (which hardcodes 0.94). Either use the constant or remove it. Clean up the six-threshold proliferation to two: general (0.85) and strict (0.93).

P2
Fix split_band_by_max_r_subpeaks: compare all adjacent peak pairs, not just extremes

When a band has 3+ discrete max_r grid bins, the current code only compares the lowest and highest. Implement single-linkage: compare all N−1 adjacent pairs; split at the first pair where cosine < threshold.

P3
Add golden-type-count tests per material

The current test only checks PBC painting correctness. Add a fast test that runs the full typing pipeline on each benchmark MOF (or a precomputed segmentation fixture) and asserts expected type counts. This prevents regression as the logic is simplified.
